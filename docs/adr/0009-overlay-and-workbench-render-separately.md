# 注入覆盖层用原生 DOM，工作台用 React

注入模式与独立工作台都要渲染设备框与工具条，但运行环境不同。

决定：两者各自实现。注入模式通过 `scripting.executeScript` 注入一个自包含函数，用原生 DOM 在 closed Shadow DOM 内绘制工具条与设备框；独立工作台是普通 React 应用，用组件渲染。

理由：注入模式若引入 React，需要把框架打进每个被注入的页面（约 200KB），且与宿主页的全局状态存在冲突风险；若让工作台也用原生 DOM，则要在纯 React 应用里混入手写 DOM，样式与状态管理割裂。两边的约束本来就不同——注入侧需要样式隔离，工作台不需要——因此各自用最合适的工具。

重复的只有工具条那几行控件代码，可控。设备几何、遮挡层形状与样式这类**会算错**的部分不重复：它们放在 `utils/viewport-transform.ts` 与 `utils/mask-style.ts`，由 background 预先算好，作为纯数据传给注入函数。注入函数因此不需要引用任何模块作用域的值，序列化后依然完整。
