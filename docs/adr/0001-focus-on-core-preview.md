# 聚焦核心预览，砍掉周边能力

经过功能盘点，当前仓库包含单设备模拟、多设备无限画布对比、设备编辑器、JSON 导入导出、截图、localhost 滚动/导航同步桥、安全区变量注入等大量能力。这些能力大多是半成品，共同造成"UI 和功能都太杂"的感受。

决定：重构后只保留**核心预览**——把目标页装进一个带正确视口、安全区和设备外壳的框里。明确砍掉：多设备对比模式、截图、滚动/导航同步桥、localhost 安全区变量注入、设备 JSON 编辑与导入导出。系统设备只读，自定义设备仅支持名称、视口宽高、安全区四值（无 DPR、无外壳、无摄像头装饰）。

理由：用户的核心痛点是"预览自己正在开发的页面在移动端的 UI 表现"，其他能力服务于低频边缘场景且每个都带"在某些情况下不工作"的 caveat，保留它们会让复杂度翻倍并稀释主线体验。砍掉的代码一旦需要可作为独立功能后续重新引入，比维护半成品更便宜。
